# 설계의 이유 — 공학 쇼츠 제작 작업 지침

이 폴더는 유튜브 채널 **「설계의 이유」**(@설계의이유)의 공학 설명 영상을 만드는 작업장이다.
건축·토목·조선·항공·고대 기술의 구조를 3D 인포그래픽으로 60초 안에 풀어내는 세로형 쇼츠가 기본 산출물이다.

작업을 시작하기 전에 이 문서를 끝까지 읽는다.
프로젝트 폴더에 `CODEX_ENGINEERING_SHORTS_PRODUCTION_SYSTEM.md` 가 있으면 그것도 함께 읽고,
세부 절차는 그 문서를, 엔진과 비용 규칙은 이 문서를 따른다. 두 문서가 어긋나면 이 문서가 우선한다.

## 불변 제작 사슬

```
SCRIPT → CLEAN → INFO → VIDEO → EDIT
```

이 순서는 바뀌지 않는다. 앞 단계가 승인되지 않으면 다음 단계로 넘어가지 않는다.

## 시작점 — 기획서가 있으면 그것으로 만든다

프로젝트 폴더를 열면 **가장 먼저 이것부터 확인한다.**

```
폴더 안에 기획서 .md 파일이 있는가?
  ├─ 있다  → 그것으로 만든다. 대본을 새로 쓰지 않는다.
  └─ 없다  → 검색으로 사실을 확인한 뒤 기획서를 직접 작성한다.
```

기획서는 「공학 쇼츠 기획실」에서 뽑은 문서이며 탭 구조를 그대로 담고 있다.
**탭이 곧 제작 단계에 대응하므로** 아래 파일로 옮겨 담고, 없는 단계만 새로 만든다.

| 기획서 탭 | 옮겨 담을 파일 |
|---|---|
| 01 대본 | `script/APPROVED_NARRATION_KR.md` |
| 02 장면 설계 | `manifests/IMAGE_SEQUENCE.md` |
| 03 키프레임 프롬프트 | `prompts/CLEAN_KEYFRAME_PROMPTS.md` 와 `prompts/INFOGRAPHIC_KEYFRAME_PROMPTS.md` |
| 04 영상 프롬프트 | `prompts/VIDEO_GENERATION_PROMPTS.md` |
| 05 자막 | `edit/subtitles_*.srt` |
| 06 업로드 정보 | `script/TITLE_DESCRIPTION.md` |
| 사실 확인 | `script/SOURCE.md` |

### 기획서를 다룰 때 지킬 것

1. **대본의 내레이션 전문은 한 줄이 한 장면이다.**
   장면 수를 추측하지 않는다. 줄 수가 곧 장면 수다.
   장면 식별자는 줄 번호를 따라 `S01A`, `KF-01A`, `CLIP01` 로 붙인다.

2. **프롬프트를 처음부터 다시 쓰지 않는다.**
   기획서에 이미 키프레임 프롬프트와 영상 프롬프트가 들어 있다.
   할 일은 거기에 이 문서의 엔진 규칙을 입히는 것뿐이다.
   - 영상: `kling3_0`, `sound: "off"`, 9:16, start=CLEAN, end=INFO
   - 이미지: `nano_banana_pro`, 2k
   - `"anchor dot"` 이라는 표현이 있으면 `"small marker dot"` 으로 바꾼다

3. **기획서의 추정 수치는 검색으로 확인한 뒤 고친다.**
   확인한 근거는 `script/SOURCE.md` 에 남긴다.
   고친 수치는 대본·자막·프롬프트 전체에 일관되게 반영한다.

4. **길이는 기획서에 적힌 값을 따른다.** 60초든 80초든 기획서가 기준이다.
   클립 길이는 나레이션 문장 길이에 맞춘다. 4초를 기본으로 하되 3~7초 범위에서 조절한다.

5. 기획서 내용이 이 문서의 규칙과 어긋날 때만 고친다.
   **무엇을 왜 고쳤는지 반드시 보고한다.** 말없이 바꾸지 않는다.

### 기획서가 있으면 승인 게이트가 줄어든다

기획서에 이미 담긴 단계는 사용자가 기획실에서 이미 검토한 것이다.
따라서 아래 게이트에서는 **내용을 확인만 하고 멈추지 않는다.**

- 1 주제와 논지 / 2 대본 / 3 장면 지도 → 기획서로 대체
- 4 CLEAN 프롬프트 / 8 영상 프롬프트 → 기획서 내용에 엔진 규칙을 입힌 결과를 보여 주고 멈춘다

**크레딧이 드는 게이트(5·7·9)는 기획서가 있어도 반드시 멈추고 승인을 받는다.**

## 승인 게이트

아래 순서를 지킨다. 사용자가 명시적으로 건너뛰라고 하지 않는 한 각 게이트에서 멈추고 승인을 받는다.

1. 주제와 공학적 논지
2. 대본
3. 장면 지도와 키프레임 수
4. CLEAN 생성 프롬프트
5. CLEAN 결과 검수
6. INFO 2차 편집 프롬프트
7. INFO 결과 검수
8. 영상 생성 프롬프트
9. MP4 검수와 파일명 순서
10. 최종 편집과 공개용 문안

이미 완료된 단계는 다시 만들지 않는다. 새 작업을 시작하기 전에
`manifests/PROJECT_STATUS.md` 와 실제 폴더를 함께 확인하고 마지막 검증된 지점부터 이어 간다.

## 폴더 구조

영상 하나마다 폴더 하나를 만든다. 쇼츠는 `제목_쇼츠`, 미드폼(가로 16:9, 약 3분)은 `제목(미드)`.

```
[프로젝트]/
  script/      APPROVED_NARRATION_KR.md, SOURCE.md, TITLE_DESCRIPTION.md
  clean/       CLEAN 키프레임
  info/        INFO 키프레임
  video/       생성된 클립
  edit/        make_tts.py, overlay.py, overlays.py, kenburns.py, assemble.py
  manifests/   PROJECT_STATUS.md, IMAGE_SEQUENCE.md, jobs.json
  prompts/     CLEAN_KEYFRAME_PROMPTS.md, INFOGRAPHIC_KEYFRAME_PROMPTS.md,
               VIDEO_GENERATION_PROMPTS.md
```

식별자는 끝까지 일관되게 쓴다. 장면 `S01A`, 키프레임 `KF-01A`, 클립 `CLIP01`.
CLEAN, INFO, MP4 는 일대일로 대응해야 한다.

## 엔진과 단가

가격은 추정이 아니라 거래 내역과 사전 조회로 확인한 값이다.

| 단계 | 엔진 | 설정 | 단가 |
|---|---|---|---|
| 나레이션 | edge-tts 선희 `ko-KR-SunHiNeural` | 48kHz mono | **무료** |
| CLEAN | `nano_banana_pro` | 2k, 쇼츠 9:16 / 미드폼 16:9 | 2 / 장 |
| INFO | `nano_banana_pro` | CLEAN job id 를 `image_references` 로 | 2 / 장 |
| 영상 | **`kling3_0`** | **`sound: "off"`**, 720p, start=CLEAN, end=INFO | **초당 1.25** |

### 영상 엔진은 Kling 3.0 으로 고정한다

기존 체계는 `wan3_0` 을 썼다. 같은 길이에서 Kling 3.0 이 28.6% 싸다.

| 길이 | Kling 3.0 `sound: off` | Wan 3.0 | 차액 |
|---:|---:|---:|---:|
| 4초 | **5.00** | 7.00 | 2.00 |
| 5초 | **6.25** | 8.75 | 2.50 |
| 7초 | **8.75** | 12.25 | 3.50 |

4초 클립 15개짜리 쇼츠 한 편 기준으로 75 대 105, 편당 30 크레딧이 차이 난다.

**`sound` 기본값은 `on` 이고 켜면 초당 1.75 로 올라 Wan 과 같아진다.**
페이로드에서 반드시 `"sound": "off"` 를 명시한다. 이 한 줄이 절감액의 전부다.
나레이션과 BGM 은 편집 단계에서 얹으므로 생성된 소리는 어차피 버려진다.

Kling 3.0 은 `start_image` 와 `end_image` 를 모두 지원하므로 CLEAN→INFO 수렴 방식이 그대로 작동한다.
청동검 프로젝트에서 이미 같은 방식으로 성공한 전례가 있다.

해상도와 프레임 장수는 가격에 관여하지 않는다. **길이만이 비용 변수다.**

## 영상 프롬프트 규칙

기본 클립은 **4.0초, 세로 9:16, 컷 없는 단일 촬영**이다.

CLEAN 이 진짜 첫 프레임이다. INFO 는 최종 그래픽 상태의 목표 참조일 뿐,
첫 프레임으로 쓰거나 평면 판처럼 움직이게 하지 않는다.

4초 구성 타이밍.

| 구간 | 내용 |
|---|---|
| 0.0–0.4 | CLEAN 만. 카메라 이동과 자연스러운 환경 움직임 시작 |
| 0.4–0.9 | 해당 구조·현상 위에 공학적 기준점이 점등 |
| 0.9–1.7 | 호출선·파면·치수선·흐름 경로·화살표 몸통이 바깥으로 뻗어 나감 |
| 1.7–2.6 | 작은 한국어 기술 라벨과 검증된 수치가 조립됨. 화살촉은 몸통이 생긴 뒤에 |
| 2.6–3.4 | 하중·압력·유체·재료·공정·에너지 펄스가 경로를 따라 이동 |
| 3.4–4.0 | INFO 목표 상태로 정착하고 읽히는 상태 유지 |

지켜야 할 것.

- 장면당 절제된 카메라 이동 한 번만. 대략 5~15도 범위
- 허용 이동: 완만한 orbit, dolly, tracking
- 카메라와 그래픽은 독립적으로 움직인다. 그래픽은 실제 3차원 공간에 고정된다
- 원근·시차·가림을 보존한다
- 모든 흐름에는 시작점, 방향, 상호작용 경계, 결과가 있다
- `"anchor dot"` 이라는 표현은 쓰지 않는다. `"small marker dot"` 으로 쓴다

금지.

- 모든 그래픽이 동시에 전체 화면에 페이드인
- 평면 HUD 처럼 보이는 배치, 떨리는 글자, 뒤집힌 화살표
- 과도한 네온, 판타지 에너지, 구조 변형, 물체 복제
- 360도 회전, 휩 팬, 카메라 롤
- 나레이션·대사·음악·새 자막·로고·워터마크 생성

세로 프레임에 가로형 구도를 요청하면 장면이 90도 돌아갈 수 있다.
그럴 때는 "카메라 쪽으로 비스듬히" 구도로 바꿔 요청한다.

## 인포그래픽 스타일

정적인 주석은 만들지 않는다. 색 화살표가 그려지며 뻗고, 흐름 대시가 움직이고,
라벨이 튀어나오는 애니메이션으로 만든다. 과하지 않게.

색 규칙: heat 주황빨강(외부 열·더운 공기), cold 시안(찬 공기·물),
struct 청백(구조·치수), gold 핵심 수치, red X / green 체크(판정).

라벨은 화면 하단 자막 영역을 피한다. 밝은 상자에는 진한 글씨.
이미지 안 문구는 한국어로 쓴다.

## 대본 논리

대본을 쓰기 전에 네 가지를 먼저 정한다.

1. **중심 질문** — 계속 보게 만드는 공학적 수수께끼
2. **핵심 메커니즘** — 그 문제를 푸는 구조·장치·물리적 개입
3. **보이는 물리 흐름** — 공기·물·흙·열·압력·하중·진동 중 화면에 보일 수 있는 것
4. **차별점** — 비슷한 사례와 이 대상을 가르는 성질

전개는 제약과 통념 → 커지는 실패 위험 → 결정적 개입 → 흐름과 힘의 변화 →
구조적 반응 → 성능 이득 → 현실의 비용과 한계 → 간결한 결론 순으로 간다.
앞의 3분의 1에서 질문과 위험을 키우고, 나머지에서 인과로 푼다.

단순화는 허용하지만 결정적 허위, 근거 없는 수치, 가짜 정밀도는 만들지 않는다.
불확실한 수치는 검색으로 확인한 뒤 쓴다.

## 나레이션과 마무리

- 나레이션은 edge-tts 선희. 숫자는 한글로 풀어 쓴다. "삼십 센티미터", "천칠백삼십팔년"
- 자막 MarginV 는 쇼츠 45, 미드폼 15. Malgun Gothic Bold 로 굽는다
- 정지 이미지 줌은 ffmpeg zoompan 을 쓰지 않는다. `kenburns.py` 의 서브픽셀 아핀을 쓴다
- BGM 선택 우선순위: 고대·역사·자연물 소재 > 긴장·반전 구조 > 메인. 묻지 말고 고른다
- 음량은 쇼츠 -6dB, 미드폼 -3dB. 사이드체인 덕킹, 끝 2.5초 페이드아웃
- **모든 영상 끝에 "구독, 좋아요는 제게 큰 힘이 됩니다." 마무리 장면을 붙인다**
- **업로드 파일은 항상 `final_*_sub_outro.mp4`**

## 비용을 쓰기 전에

1. 생성 전에 `balance` 로 잔액을 확인한다.
2. 예상 차감액을 산출해 사용자에게 보고하고 승인을 받는다.
   설정에 대한 답변은 승인이 아니다.
3. 한 번 생성하면 결과를 확인한 뒤 다음을 생성한다.
   확인 없이 연달아 던지지 않는다.
4. 같은 정보를 두 번 전달하는 장면은 만들지 않는다.
   각도만 다른 변주는 이미지를 새로 뽑을 일이 아니라 카메라 무빙으로 해결한다.
5. 결함이 한 자산에만 있으면 그 자산만 고친다. 전체를 다시 만들지 않는다.

비용 산출과 중복 탐지 구현은 상위 폴더의 `kling/kling_pipeline.py` 에 있다.

## 소통

한국어로 답한다. 수백 크레딧이 드는 결정이나 화질 선택은 선택지와 비용을 함께 제시한다.
그 외 제작 단계는 묻지 않고 진행한다.
