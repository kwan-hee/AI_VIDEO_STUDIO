# 네이버 블로그 독후감 작성 스킬

책 제목 하나만 있어도 사실 검증과 이미지 수집을 거쳐, 네이버 블로그에 바로 붙여 넣을 수 있는 독후감 포스팅을 완성한다.

결과물은 항상 두 가지다. 하나는 네이버 에디터에 그대로 붙여 넣는 **본문 텍스트 파일**이고, 다른 하나는 이미지 자료와 메타 정보까지 한눈에 확인하는 **완성형 HTML 파일**이다. 두 파일은 같은 데이터에서 생성되므로 내용이 어긋나지 않는다.

## 이 스킬이 지키는 네 가지 기준

1. **사람이 쓴 문체**: 기계적인 표현을 걸러 내고, 읽은 사람의 판단과 온도가 드러나게 쓴다.
2. **네이버 검색 노출**: 제목과 첫 문단, 소제목, 해시태그에 핵심 키워드를 의도적으로 배치한다.
3. **분량 확보**: 본문 2,000자 이상을 안정적으로 채우되, 분량을 채우려고 같은 말을 반복하지 않는다.
4. **사실 검증과 출처**: 저자, 출간 연도, 수상 이력, 인용 문장은 반드시 확인한 근거를 남긴다.

## 화자 설정

이 스킬의 화자는 **정보 전달형 리뷰어**다. 감정을 앞세우는 감상문이 아니라, 책을 실제로 읽고 정리해서 알려 주는 사람의 목소리로 쓴다.

구체적으로는 다음을 뜻한다. 판단은 분명하게 밝히되 근거를 함께 제시하고("이 책은 좋다"가 아니라 "이 책은 3장부터 밀도가 급격히 올라가는데, 그 이유는…"), 개인적 감상은 글 전체의 20퍼센트 안쪽으로 유지하며, 독자가 이 책을 읽을지 말지 판단할 재료를 준다. 과장된 찬사와 무조건적인 추천은 신뢰를 깎아 먹으므로 피한다.

## 실행 순서

### STEP 0 — 입력 유형 판별

사용자가 준 재료를 먼저 분류한다. 어떤 유형이냐에 따라 STEP 1에서 조사할 범위가 달라진다.

| 유형 | 예시 입력 | 처리 방향 |
|---|---|---|
| 주제어만 | "『싯다르타』 독후감 써줘", "헤르만 헤세 블로그 글" | STEP 1의 조사를 전면적으로 수행한다 |
| 메모·밑줄 | 인상 깊은 문장 목록, 짧은 감상 메모 | 사용자의 문장을 글의 뼈대로 삼고, 사실 정보만 보충한다 |
| 자막·원문 | 유튜브 북리뷰 자막, 강연 녹취 | 원문의 관점을 살리되 출처를 명시하고, 자동 자막의 인명 오기를 반드시 교정한다 |

**중요한 구분이 하나 있다.** 사용자가 책을 직접 읽었는지 여부를 알 수 없다면, 읽은 척하는 1인칭 체험 서술("밑줄을 그으며 읽었습니다")을 지어내지 않는다. 대신 "이 책이 지금 다시 읽히는 이유", "이 책이 다루는 문제"처럼 검증 가능한 사실에 근거한 서술로 시작한다. 사용자가 메모나 감상을 제공했다면 그것은 실제 독서의 근거이므로 1인칭을 적극적으로 쓴다.

책이 여러 판본으로 나와 있거나 동명의 책이 존재하면, 조사 결과를 근거로 가장 널리 읽히는 판본을 선택하고 그 사실을 사용자에게 한 줄로 알린다. 진행을 멈추고 되묻지 않는다.

### STEP 1 — 사실 조사

웹 검색으로 아래 항목을 확인한다. 확인되지 않은 항목은 비워 두고, 글에서도 언급하지 않는다. 추측으로 채우면 그 한 줄 때문에 글 전체의 신뢰가 무너진다.

**필수 확인 항목**
- 원제와 한국어 제목, 저자명(원어 표기 포함), 번역자
- 출판사, 국내 출간 연도, 원서 출간 연도, 쪽수
- 장르와 분류, 대표적인 수상 이력
- 목차 또는 주요 구성
- 대표적인 평가와 논쟁점(호평과 비판을 모두 확인한다)
- 저자의 다른 대표작, 이 책이 쓰인 시기의 저자 상황

**조사 도구**는 환경에 따라 가용한 것을 사용한다. 네이버 검색 도구(`search_book`이 없다면 `search_encyc`, `search_webkr`, `search_blog`)를 쓸 수 있으면 국내 출간 정보에 가장 정확하다. 그 밖에 웹 검색과 페이지 가져오기 도구를 함께 사용해 교차 확인한다. 상세한 검증 절차와 출처 우선순위는 `references/sourcing.md`를 참조한다.

원서 출간 연도와 국내 출간 연도는 자주 혼동된다. 두 연도가 다르면 글에서 반드시 구분해서 적는다.

### STEP 2 — 리뷰의 축 정하기

조사가 끝나면 본문을 쓰기 전에 **이 글이 붙잡을 질문 하나**를 정한다. 이 축이 없으면 글은 줄거리 요약과 감상 나열로 흩어지고, 독자는 끝까지 읽지 않는다.

축은 다음 형태로 한 문장으로 적어 둔다.
- "진리는 가르칠 수 있는가라는 질문을, 한 사람의 실패한 일생으로 검증하는 소설"
- "습관을 의지의 문제가 아니라 설계의 문제로 옮겨 놓은 실용서"

그리고 이 책을 **누가 읽으면 좋은지, 누구에게는 맞지 않는지**를 각각 한 줄로 정해 둔다. 정보 전달형 리뷰어의 글에서 독자가 가장 고마워하는 부분이 바로 이 판단이다.

### STEP 3 — 이미지 자료 수집

책 관련 이미지를 찾아 최소 두 건, 가능하면 세 건을 확보한다.

**수집 대상의 우선순위**
1. 도서 표지 이미지(출판사, 네이버 책, 알라딘, 교보문고 등 서지 페이지)
2. 저자 사진(위키미디어 공용처럼 재사용 조건이 명시된 출처를 우선한다)
3. 책의 배경이 되는 장소, 시대, 개념을 보여 주는 이미지
4. 원서 표지, 초판본, 다른 판본의 표지

**저작권 처리 원칙**은 단순하다. 이미지 파일을 직접 복제해 배포하지 않고, **URL과 출처를 함께 제공**한다. HTML 미리보기에서는 원본 URL을 그대로 불러와 표시하고, 본문 텍스트에는 "[ 이미지 ① 삽입 ]"이라는 안내와 캡션을 넣어 사용자가 네이버 에디터에서 직접 삽입하도록 한다. 생성형 도구로 만든 그림은 사용하지 않는다. 책 리뷰에서 가짜 이미지는 글 전체를 의심받게 만든다.

이미지마다 캡션을 "▲ 설명 / 출처: 매체명" 형식으로 준비한다. 네이버는 이미지 캡션의 텍스트도 검색에 반영하므로, 캡션에 책 제목이나 저자명을 자연스럽게 포함시킨다.

### STEP 4 — 본문 집필

구조는 아래를 기본으로 하되, 책의 성격에 따라 섹션 제목과 순서를 조정한다. 소설과 실용서는 독자가 궁금해하는 지점이 다르므로 같은 틀을 기계적으로 반복하지 않는다.

```
[도입부 2~3단락]
  - 이 책이 지금 읽히는 이유 또는 독자가 겪는 구체적 상황
  - 이 책이 붙잡은 질문 한 줄 (STEP 2의 축)
  - 이 글에서 무엇을 다루는지

[ 이미지 ① 삽입 ] ▲ 캡션

[h3 섹션 1 — 책과 저자의 배경]
  - 저자가 이 책을 쓴 시기와 상황, 출간 정보
  - 이 책이 놓인 맥락 (2~3단락, 400자 이상)

[h3 섹션 2 — 책이 말하는 것]
  - 핵심 내용을 장면 또는 논지 단위로 2~3개 짚는다
  - 소설이면 결말을 밝히지 않는다 (3~4단락, 600자 이상)

[ 이미지 ② 삽입 ] ▲ 캡션

[h3 섹션 3 — 밑줄 그은 문장]
  - 인용 1~3개, 각각 "인용 → 쉽게 풀이 → 왜 마음에 남는지" 순서
  - 인용의 출처와 성격을 밝힌다 (400자 이상)

[ 이미지 ③ 삽입 ] ▲ 캡션

[h3 섹션 4 — 누가 읽으면 좋은가]
  - 추천 대상과 비추천 대상을 모두 밝힌다
  - 함께 읽으면 좋은 책 1~2권 (300자 이상)

[💡 한 줄 정리 callout]

[마무리 1단락 — 여운 있는 문장으로 닫는다]

[도서 정보 + 출처 표기]
```

**분량 기준**: 본문 2,000~2,500자(공백 포함), 소제목(h3) 최소 3개, 이미지 삽입 안내 2~3곳, 인용 1개 이상, 검증된 사실 정보 3개 이상(출간 연도, 쪽수, 수상 이력, 판매량 등).

**문체**는 이 스킬의 핵심이므로 집필 직전에 `references/writing-style.md`를 반드시 읽는다. 거기에는 피해야 할 표현 목록과 좋은 예시가 대조 형태로 정리되어 있다. 요약하면 이렇다. "살펴보겠습니다", "알아보도록 하겠습니다", "매우 중요합니다" 같은 관용적 서두를 쓰지 않고, 문장 길이를 의도적으로 들쭉날쭉하게 만들며, 판단에는 근거를 붙이고, 단정이 부담스러운 대목에서는 유보적으로 적는다.

**스포일러 처리**: 소설이나 서사가 있는 책은 결말을 밝히지 않는다. 다만 "결말은 밝히지 않겠습니다"라고 굳이 선언하기보다, 결정적인 장면 직전에서 서술을 멈추고 그 장면이 던지는 질문으로 넘어가는 편이 훨씬 자연스럽다.

### STEP 5 — SEO 메타 정보 작성

`references/seo-naver.md`의 규칙에 따라 아래를 작성한다.

- **제목 3개**와 추천 1개: 각 제목은 25~35자, 핵심 키워드를 앞쪽에 배치한다
- **메타 설명**: 80~100자, 검색 결과에 노출되는 문장이다
- **해시태그 10~15개**: 책 제목, 저자명, 장르, 독자 상황, 계절성 키워드를 섞는다
- **핵심 키워드 3개**와 본문 내 등장 횟수: 주 키워드는 본문에서 5~7회 반복하되, 억지로 끼워 넣어 문장이 어색해지면 노출보다 손해다

### STEP 6 — 파일 생성

집필 결과를 `post.json`으로 정리한 뒤, 번들된 스크립트를 실행한다. 스크립트가 본문 텍스트와 HTML을 같은 데이터에서 생성하므로 두 결과물의 내용이 어긋나지 않는다.

```bash
python3 <스킬경로>/scripts/build_post.py post.json --outdir outputs/
```

출력물은 두 개다.
- `outputs/<슬러그>.txt` — 네이버 에디터 복붙용 본문
- `outputs/<슬러그>.html` — 탭 4개(블로그 본문 / 이미지 자료 / 메타 정보 / 사실 확인)와 복사·다운로드 버튼을 갖춘 문서

`post.json`의 구조와 각 필드의 의미는 `references/post-json.md`에 정리되어 있고, 완성된 예시는 `assets/example-post.json`에 있다. 처음 작성한다면 예시를 복사해 값만 바꾸는 편이 빠르다. 스크립트는 필수 필드가 빠지면 어느 필드가 왜 필요한지 알려 주며 중단하므로, 오류 메시지를 보고 수정한다.

저장 위치를 사용자가 지정하지 않았다면 현재 작업 디렉터리 아래 `outputs/`를 사용한다. 파일을 사용자에게 전달하는 도구(`present_files` 또는 `SendUserFile`)가 있으면 두 파일을 모두 전달한다.

### STEP 7 — 자체 점검

파일을 전달하기 전에 아래를 확인한다. 하나라도 어긋나면 고친 뒤 다시 생성한다.

- [ ] 본문이 2,000자 이상인가? (스크립트가 공백 포함 글자 수를 출력한다)
- [ ] 소제목이 3개 이상이고, 각 섹션이 400자 이상인가?
- [ ] "살펴보겠습니다", "알아보겠습니다", "~에 대해 알아보도록" 같은 표현이 없는가?
- [ ] 모든 문단이 비슷한 길이로 늘어서 있지 않은가?
- [ ] 추천 대상과 함께 **비추천 대상 또는 한계**를 밝혔는가?
- [ ] 출간 연도, 저자 정보 등 검증한 사실이 3개 이상 들어갔는가?
- [ ] 확인하지 못한 정보를 추측으로 적지 않았는가?
- [ ] 이미지마다 URL, 출처, 캡션, 삽입 위치가 모두 있는가?
- [ ] 소설이라면 결말이 노출되지 않았는가?
- [ ] 해시태그가 10개 이상이고, 주 키워드가 본문에 5회 이상 등장하는가?

## 사용자에게 보고하는 방식

파일을 만든 뒤에는 결과물을 장황하게 되풀이하지 않는다. 사용자가 알아야 할 것은 다음 네 가지다.

1. 어떤 책을 어떤 축으로 다뤘는지 한두 문장
2. 본문 글자 수와 추천 제목
3. 확인하지 못해 글에서 뺀 정보가 있다면 그 사실
4. 파일 경로

그다음 사용자가 바꾸고 싶어 할 만한 선택지를 두세 개 제시한다. 제목 교체, 분량 조정, 특정 섹션 보강 같은 것이다.

## 참조 파일

작업 단계에 맞춰 필요한 것만 읽는다.

- `references/writing-style.md` — 독후감 전용 문체 가이드. STEP 4 집필 직전에 반드시 읽는다.
- `references/seo-naver.md` — 네이버 검색 노출 규칙. STEP 5에서 읽는다.
- `references/sourcing.md` — 사실 검증 절차, 출처 우선순위, 인용과 이미지 저작권 처리. STEP 1과 STEP 3에서 읽는다.
- `references/post-json.md` — `post.json`의 필드 정의와 예시. STEP 6에서 읽는다.
- `assets/example-post.json` — 모든 필드가 채워진 완성 예시.
- `scripts/build_post.py` — 본문 텍스트와 HTML을 생성하는 스크립트.
