# 사실 검증과 출처 처리

책 리뷰에서 틀린 사실 하나는 글 전체의 신뢰를 무너뜨린다. 출간 연도를 잘못 적거나 저자의 다른 작품을 혼동하면, 독자는 나머지 판단도 믿지 않는다. 그래서 검증은 집필보다 먼저 온다.

---

## 1. 출처 우선순위

같은 정보가 서로 다르게 적혀 있을 때는 아래 순서로 신뢰한다.

1. **출판사 공식 도서 페이지** — 국내 출간 정보의 1차 출처다.
2. **국립중앙도서관 소장 정보, ISBN 검색** — 서지 정보가 가장 정확하다.
3. **네이버 책, 알라딘, 교보문고, 예스24** — 쪽수, 판형, 출간일, 목차를 확인하기 좋다.
4. **위키백과(영문 우선), 저자 공식 페이지, 수상 기관 공식 발표** — 원서 정보와 수상 이력.
5. **언론 서평, 학술 서평** — 평가와 논쟁점.
6. **개인 블로그, 유튜브 자막** — 참고만 하고, 사실 확인의 근거로 삼지 않는다.

6번에서 얻은 내용을 글에 쓸 때는 반드시 **"영상에서 소개된 표현"**, **"한 서평에서 제기된 평가"**처럼 성격을 밝힌다. 자동 생성 자막은 인명과 지명을 자주 틀리므로, 고유명사는 예외 없이 1~4번으로 다시 확인한다.

---

## 2. 반드시 교차 확인하는 항목

아래 항목은 두 곳 이상에서 일치를 확인한다. 자주 틀리는 것들이다.

- **원서 출간 연도와 국내 출간 연도**: 두 연도가 다르면 글에서 구분해서 적는다.
- **번역자와 판본**: 인용 문장은 번역본마다 다르다. 인용을 쓴다면 어느 번역본인지 밝히는 편이 안전하다.
- **저자의 생몰 연도와 수상 이력**: 수상 연도와 수상 대상 작품을 혼동하기 쉽다.
- **판매 부수, 베스트셀러 순위**: 출처와 기준 시점을 함께 적지 않으면 쓰지 않는다.
- **동명이인, 동명의 책**: 제목이 같은 다른 책이 있는지 먼저 확인한다.

---

## 3. 확인하지 못한 정보의 처리

**추측으로 채우지 않는다.** 이 원칙에는 예외가 없다.

확인되지 않은 항목은 세 가지 중 하나로 처리한다.

1. 글에서 뺀다. 대부분의 경우 이 선택이 옳다.
2. 불확실성을 드러내며 적는다. ("국내에는 여러 번역본이 나와 있습니다"처럼 범위로 적는다.)
3. 사용자에게 알린다. 결과를 보고할 때 "출간 부수는 공식 자료를 찾지 못해 넣지 않았습니다"라고 한 줄로 전한다.

---

## 4. 인용 처리

- 한 인용은 **두세 문장, 60자 안팎**을 넘기지 않는다. 원문을 길게 옮기는 것은 저작권 침해가 될 수 있고, 글의 중심도 흐려진다.
- 인용에는 출처를 붙인다. 최소한 책 제목과 번역본 정보다.
- 요약과 인용을 섞지 않는다. 큰따옴표 안에 들어간 문장은 원문 그대로여야 한다. 풀어 쓴 문장은 따옴표 밖에 둔다.
- 2차 자료에서 얻은 인용은 그 사실을 밝힌다.

---

## 5. 이미지 저작권

**원칙: 파일을 복제해 배포하지 않고, URL과 출처를 제공한다.**

| 이미지 종류 | 처리 |
|---|---|
| 도서 표지 | 서점·출판사 페이지의 이미지 URL과 출처를 함께 제공한다. 표지 이미지는 도서 소개 목적의 인용으로 통용되지만, 출처 표기는 반드시 한다 |
| 저자 사진 | 위키미디어 공용처럼 재사용 조건이 명시된 출처를 우선한다. 라이선스 표기(CC BY-SA 등)를 캡션에 넣는다 |
| 언론 보도 사진 | 직접 삽입하지 않는다. 기사 링크를 제공한다 |
| 생성형 도구로 만든 그림 | 사용하지 않는다. 책 리뷰에서 가짜 이미지는 글 전체를 의심받게 만든다 |
| 사용자가 직접 찍은 사진 | 가장 좋다. 실제 경험의 근거가 되고 유사 문서 판정도 피한다 |

캡션 형식은 `▲ 설명 / 출처: 매체명`으로 통일한다. 라이선스가 있으면 `▲ 설명 / 출처: Wikimedia Commons (CC BY-SA 4.0)`처럼 덧붙인다.

---

## 6. 검증 기록 남기기

조사한 사실은 `post.json`의 `fact_check` 항목에 정리한다. 항목마다 **확인한 값**과 **출처 URL**을 적는다. 이 기록은 생성되는 HTML의 '사실 확인' 탭에 그대로 실린다.

기록을 남기는 이유는 두 가지다. 나중에 사용자가 수정할 때 근거를 다시 찾지 않아도 되고, 글에 오류 지적이 들어왔을 때 즉시 대조할 수 있다.

```json
"fact_check": [
  {"item": "원서 출간", "value": "1922년 독일", "source": "https://..."},
  {"item": "저자 생몰", "value": "1877~1962", "source": "https://..."},
  {"item": "노벨문학상", "value": "1946년 수상", "source": "https://..."}
]
```
